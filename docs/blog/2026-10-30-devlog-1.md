# 【開発日誌 #1】Rustとmrubyedgeで作るレトロゲームエンジン「Usakame」誕生と、AI時代の「ガチャキー」テスト駆動開発

**対象期間**: 2026年10月17日 〜 10月30日

個人開発で、Rust（Macroquad）と軽量Ruby VM「mrubyedge」を組み合わせたレトロゲームエンジン **「Usakame（うさかめ）」** の開発を始めました。最初の2週間でエンジンのコアからAI連携まで一気に形になったので、設計の裏話をまとめます。

![Rabbit Knight - ドット絵と内蔵絵文字が共存するサンプルゲーム](../../screenshots/2026-10-25_rabbit_knight_latest.png)

## 1. なぜ「Ruby」で「昔のBASICのような1ファイル完結」なのか？

私はRubyが好きで、「いつでもRubyで気軽にゲームを作れる環境が欲しい」と常々思っていました。

Usakameの最大の特徴は、**ゲームのロジックだけでなく、スプライト（ドット絵）・タイルマップ・効果音（SFX）・BGMに至るまで、すべて1つの `.rb` ファイルの中にテキストで記述できる**ことです。Rubyスクリプト末尾の `__END__` 以降に、`@SPRITE` や `@MAP` といったセクションを書いてリソースを定義します（内蔵Twemojiによる絵文字スプライトや、美咲フォント・東雲フォントによる日本語表示もそのまま使えます）。

```ruby
def update
  # ゲームロジック
end

def draw
  cls(0)
  spr(:hero, 120, 120)
  print_text("うさかめエンジン！", 80, 100, 7)
end

__END__
@SPRITE :hero
..7777..
.744447.
...
```

![PC-98風640x480解像度と東雲ゴシック・絵文字描画デモ](../../screenshots/2026-10-19_pc98_resolution.png)

昔のパソコンのBASICのように「リソースも含めてすべてが目の前のコード上に表現されている」状態にすることで、外部ツールの使い方を覚える手間をなくし、**初心者の人も、そしてコードを生成するAIエージェントも、目の前のコードだけに100%集中できる環境**を目指しました。

初日のうちに、`uk run`（ホットリロード実行）、`uk build`（単一実行バイナリ出力）、`uk browser`（WASMでのブラウザ動作）まで一気通貫で動くようになっています。

## 2. AIが書くmrubyedgeコードが落ちる問題と、「ガチャキー」モード（`uk check -g`）

1ファイル完結にしたことでAIエージェントにゲームを生成してもらいやすくなった一方、大きなストレスになったのが**「mrubyedgeの未実装メソッドで実行時に落ちる問題」**でした。

Usakameが採用している `mrubyedge` はWebAssembly等でも高速・軽量に動く反面、標準のCRubyやmrubyにあるメソッド（`Array#sample` や `Integer#upto` など）の一部が存在しません。AIは標準Rubyの知識でコードを書くため、`NoMethodError` を頻発させていました。

これに対して、2つの対策を打ちました。

1. **「何が使えるか・代替コードは何か」を明記した [`docs/mrubyedge_api.md`](../mrubyedge_api.md) の整備**
   （AI自身にも相談したところ、直接 `.mrb` 等を扱うより、明確なAPI一覧とイディオム変換表のドキュメントを参照させる方が圧倒的に間違えにくいとのことでした）
2. **ヘッドレス検証＆擬似ボタン連打「ガチャキーモード（`uk check -g`）」の実装**

ゲームプログラムの厄介なところは、**「起動直後のタイトル画面では落ちないが、プレイヤーがボタンを押して移動や攻撃の計算が始まった瞬間に落ちる」**ことです。
そこで、GUIウィンドウを開かずに60〜120フレーム分を高速実行する `uk check` コマンドに、**方向キーやパッドのボタンを擬似的にガチャガチャと連打しながら実行する `-g`（ガチャキー）オプション**を追加しました。

```powershell
# ウィンドウを開かず、ボタンをガチャガチャ連打しながら120フレーム分の実行時エラーを検証
uk check game.rb -g --frames 120
```

AIエージェントに「コードを書いたら必ず `uk check -g` を通すこと」をルール化した結果、生成されたゲームが起動直後や操作開始時にクラッシュすることがほぼゼロになり、さまざまなジャンルのサンプルゲームを高速に量産できるようになりました。

## 今期のその他のアップデート

* **エンジン内蔵エディタ**: Usakame自身のRubyスクリプトで動くスプライトエディタ・タイルマップエディタを実装（単一 `.rb` ファイルへの非破壊保存に対応）。
* **落ちないライブコーディング**: スクリプトエラー発生時にウィンドウを閉じず、画面上に赤枠でスタックトレースを表示し、ファイル保存で即自動復帰する仕組みを導入。
* **多彩なパレット＆UIクックブック**: `@PALETTE` によるパレット切り替えや、RPG会話ウィンドウ・コマンド戦闘UI等のクックブックを追加。
