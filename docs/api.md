# Usakame Engine API & グラフィックス・サウンド仕様書

このドキュメントでは、レトロゲームエンジン **Usakame** の現在のAPI一覧、グラフィックス描画仕様、およびサウンド機能の現状と設計方針をまとめています。

---

### 1. エンジン基本仕様

| 項目 | 仕様 |
| :--- | :--- |
| **仮想画面解像度** | `256 × 256` ピクセル固定 |
| **初期ウィンドウサイズ** | `512 × 512` ピクセル（2倍スケール、リサイズ可能・アスペクト比維持） |
| **カラーパレット** | 標準16色パレット（テキストスプライト・図形描画用）＋ フルカラーRGBA / 15-bit RGB555（PNG・絵文字スプライト用） |
| **スプライト基本サイズ** | `16 × 16` ピクセル（標準内蔵絵文字 1,400種・テキスト・Base64 PNG対応） |
| **フレームレート** | 約 60 FPS |
| **スクリプト言語** | Ruby（mrubyedge / mruby-compiler2 によるバイトコード実行） |

---

## 2. 現在のAPIリスト

すべてのエンジンAPIはRubyのトップレベル（`Object`クラスのメソッド）として定義されており、どこからでも直接呼び出すことができます。

### 2.1 ライフサイクルコールバックとシーン管理（`run` / `scene`）

Usakame では、シンプルなトップレベル関数によるループのほか、オブジェクト指向（ダックタイピング）によるクリーンな**シーン管理 API（`run` / `scene`）**をサポートしています。

#### ① クラスベースのシーン定義（推奨）

`update` および `draw` メソッドを実装した任意の Ruby オブジェクトを `run(scene_obj)`（またはエイリアス `scene(scene_obj)`）に渡すことで、ゲームループをオブジェクト指向で構築できます。

* **ダックタイピング**:
  * 渡されるオブジェクトは特定の基底クラスを継承する必要はありません。`update` や `draw` を持っていれば自動的に毎フレーム呼び出されます。
  * `update` または `draw` のどちらか片方しか定義されていない場合でもエラーにならず、存在するメソッドのみが呼び出されます。
* **遅延切り替え（フレーム境界での安全な遷移）**:
  * `run(new_scene)` を呼ぶと即座に切り替わるのではなく、次のフレームの先頭（`update` 呼び出し直前）に安全に切り替わります。
* **描画ステートの自動リセット（`reset_state: true`）**:
  * デフォルト（`reset_state: true`）では、シーン遷移時にエンジン側の描画ステート（`camera()`, `clip()`, `pal()`）が初期状態にリセットされます。
  * 前のシーンの描画設定（カメラ位置やカラーパレット置換）を引き継ぎたい場合は、`run(new_scene, reset_state: false)` と指定します。

```ruby
class TitleScene
  def update
    if btnp(4) # Z / Space でゲーム開始
      run GameScene.new
    end
  end

  def draw
    cls(1)
    print_text("TITLE SCREEN", 88, 100, 7)
    print_text("PRESS Z TO START", 76, 130, 10)
  end
end

class GameScene
  def initialize
    @x = 120
    @y = 120
  end

  def update
    @x -= 1 if btn(0)
    @x += 1 if btn(1)
    @y -= 1 if btn(2)
    @y += 1 if btn(3)

    if btnp(5) # X / Enter でポーズ画面へ
      run PauseScene.new(self)
    end
  end

  def draw
    cls(3)
    rectfill(@x, @y, 16, 16, 11)
    print_text("GAME SCENE - PRESS X TO PAUSE", 36, 16, 7)
  end
end

# ポーズ画面（ラッパーシーン方式: 前のシーンを保持して背後に描画し、復帰時にそのまま戻す）
class PauseScene
  def initialize(prev_scene)
    @prev_scene = prev_scene
  end

  def update
    if btnp(5) # 再度 X を押したらゲームシーンへ復帰
      run @prev_scene, reset_state: false
    end
  end

  def draw
    @prev_scene.draw # 背面に元のゲーム画面を描画
    rectfill(64, 80, 128, 64, 0)
    rect(64, 80, 128, 64, 7)
    print_text("PAUSED", 110, 96, 10)
    print_text("PRESS X TO RESUME", 78, 120, 7)
  end
end

# 初回シーンの起動
run TitleScene.new
```

#### ② トップレベル関数による定義（従来方式・後方互換）

スクリプト初回評価終了時点で `run`（または `scene`）が一度も呼び出されなかった場合、従来通りトップレベルの `update` / `draw` メソッドが自動的に呼び出されます。

```ruby
def update
  # 毎フレームのロジック更新
end

def draw
  # 毎フレームの描画処理
end
```

### 2.2 描画API

| メソッド | 引数とデフォルト値 | 戻り値 | 説明 |
| :--- | :--- | :--- | :--- |
| **`cls`** | `(col = 0)` | `nil` | 仮想画面全体（`clip` 指定中はクリッピング領域内）を指定したパレット色 `col` で塗りつぶしてクリアします。 |
| **`camera`** | `(x = 0, y = 0)` | `nil` | カメラオフセットを `(x, y)` に設定し、以降のすべての描画座標から `(x, y)` を減算します。引数なしで `camera()` と呼ぶと `(0, 0)` にリセットします。 |
| **`clip`** | `(x = nil, y = nil, w = nil, h = nil)` | `nil` | 画面座標系の矩形 `(x, y, w, h)` の内側のみに描画を制限（クリッピング）します。引数なしで `clip()` と呼ぶとクリッピングを解除します。 |
| **`pal`** | `(c0 = nil, c1 = nil)` | `nil` | パレット色 `c0` を `c1` に置き換えて以降の図形・テキスト・スプライトを描画します。16要素の配列 `pal([c0, c1, ...])` で一括設定も可能。`pal(c0, "#RRGGBB")` や `pal(c0, r, g, b)` で指定色番号のRGB値を動的に変更することもできます。引数なしで `pal()` と呼ぶとパレット置換、`palt`、および動的RGB変更をリセットします。 |
| **`pal_bank`** | `(id = 0)` | `nil` | 以降の図形描画やテキスト描画で使用するパレットバンクを `id` に切り替えます（`@PALETTE <id>` で定義されたRGBテーブルを適用）。引数なしで `pal_bank()` または `pal_bank(0)` と呼ぶとシステム標準パレット（PICO-8 16色）に戻します。なお、`spr_bank(id)` を呼び出した際も、同番号の `@PALETTE id` が定義されていれば自動的にパレットが連動します。 |
| **`palt`** | `(col = nil, t = true)` | `nil` | スプライト描画時にパレット色 `col` を透明（`t = true`）または不透明（`t = false`）として扱うか設定します。引数なしで `palt()` と呼ぶとリセットします（元から透明な `.` ピクセルは常に透明）。 |
| **`pset`** | `(x = 0, y = 0, col = 7)` | `nil` | 座標 `(x, y)` に色 `col` で `1 × 1` ピクセルの点を描画します。 |
| **`line`** | `(x0 = 0, y0 = 0, x1 = 0, y1 = 0, col = 7)` | `nil` | 始点 `(x0, y0)` から終点 `(x1, y1)` まで、ブレゼンハムアルゴリズムで太さ `1px` の直線を色 `col` で描画します。 |
| **`rect`** | `(x = 0, y = 0, w = 16, h = 16, col = 7)` | `nil` | 左上座標 `(x, y)` から幅 `w`、高さ `h` の枠線のみの矩形（太さ `1px`）を色 `col` で描画します。 |
| **`rectfill`** | `(x = 0, y = 0, w = 16, h = 16, col = 7)` | `nil` | 左上座標 `(x, y)` から幅 `w`、高さ `h` の塗りつぶし矩形を色 `col` で描画します。 |
| **`circ`** / **`circle`** | `(x = 0, y = 0, r = 4, col = 7)` | `nil` | 中心 `(x, y)`、半径 `r` の枠線のみの円（太さ `1px`、ドット対称）を色 `col` で描画します。 |
| **`circfill`** / **`circlefill`** | `(x = 0, y = 0, r = 4, col = 7)` | `nil` | 中心 `(x, y)`、半径 `r` の塗りつぶし円を色 `col` で描画します。 |
| **`oval`** / **`ellipse`** | `(x = 0, y = 0, rx = 6, ry = 4, col = 7)` | `nil` | 中心 `(x, y)`、水平半径 `rx`、垂直半径 `ry` の枠線のみの楕円（太さ `1px`、ドット対称）を色 `col` で描画します。 |
| **`ovalfill`** / **`ellipsefill`** | `(x = 0, y = 0, rx = 6, ry = 4, col = 7)` | `nil` | 中心 `(x, y)`、水平半径 `rx`、垂直半径 `ry` の塗りつぶし楕円を色 `col` で描画します。 |
| **`tri`** | `(x0 = 0, y0 = 0, x1 = 8, y1 = 0, x2 = 4, y2 = 8, col = 7)` | `nil` | 3頂点 `(x0, y0)`, `(x1, y1)`, `(x2, y2)` を結ぶ枠線のみの三角形を色 `col` で描画します。 |
| **`trifill`** | `(x0 = 0, y0 = 0, x1 = 8, y1 = 0, x2 = 4, y2 = 8, col = 7)` | `nil` | 3頂点 `(x0, y0)`, `(x1, y1)`, `(x2, y2)` で囲まれた塗りつぶし三角形を色 `col` で描画します。 |
| **`spr_id`** | `(name, frame = 0, loop = true)` | `Integer` | スプライト名（`Symbol` または `String`、あるいは整数ID）とフレーム番号から、割り当てられたスロットIDを高速に解決します。`frame` は整数または小数。`loop = true`（デフォルト）時はループ再生、`loop = false` 時は最終フレームでクランプ（停止）します。 |
| **`spr`** | `(id, x = 0, y = 0, flip_x = false, pal = nil)` | `nil` | スプライト番号 `id`（整数、`spr_id` の戻り値）、スプライト名（`Symbol`）、または絵文字・スプライト名（`String`）を座標 `(x, y)` に描画します。実サイズ（8x8, 16x16, 32x32等）で描画されます。第5引数に整数を渡すと一時パレットスワップ `pal` として機能します。<br>※後方互換性のため、旧シグネチャ `(id, x, y, flip_x, flip_y, rotate, scale)` やタイル数指定 `(id, x, y, w, h, ...)` の形式でも呼び出し可能です。 |
| **`spr_ext`** / **`spr_ex`** / **`spr_rot`** | `(id, x = 0, y = 0, rot = 0, scale_x = 1.0, scale_y = nil, flip_x = false, flip_y = false, pal = nil)` | `nil` | 回転・拡大縮小・上下反転・パレットスワップを指定して描画します。`scale_y` を省略（`nil`）した場合は等倍スケーリング、別々に指定した場合は縦横独立スケーリング（Squash & Stretch）が行われます。回転・スケーリングはスプライトの中心ピボット基準です。 |
| **`spr_clip`** | `(id, x, y, u, v, w, h, flip_x = false, flip_y = false, pal = nil)` | `nil` | 指定したスプライト `id`（整数、`Symbol`、`String`）の左上原点を `(0, 0)` とみなし、ローカル座標 `(u, v)` から幅 `w` × 高さ `h` ピクセルを切り抜いて画面座標 `(x, y)` に描画します。 |
| **`blt`** | `(x = 0, y = 0, bank = 0, u = 0, v = 0, w = 16, h = 16, rotate = 0, scale = 1.0, pal = nil)` | `nil` | バンク `bank` の矩形領域 `(u, v, w, h)` を画面座標 `(x, y)` にピクセル転送描画します。第3引数 `bank` にはバンク番号（整数）のほか、スプライト名（`Symbol`、例: `:hero`）を渡すこともでき、その場合は該当スプライトの左上を原点とするローカル切り抜きとして動作します。`w` や `h` に負の値を指定すると反転します。第10引数 `pal` でパレットスワップ可能です。 |
| **`map`** | `(cel_x = 0, cel_y = 0, sx = 0, sy = 0, cel_w = map.width, cel_h = map.height)` | `nil` | タイルマップのセル `(cel_x, cel_y)` から幅 `cel_w` × 高さ `cel_h` セル分の領域を、画面（ワールド）座標 `(sx, sy)` を左上基準として一括描画します（`1セル = 16 × 16`px、空マスはスキップ、タイル番号 `0` も有効なタイルとして描画されます）。 |
| **`mget`** | `(cel_x = 0, cel_y = 0)` | `Integer` / `nil` | タイルマップ上のセル `(cel_x, cel_y)` に配置されているタイル番号（スプライトID）を返します。未設定セルまたは消去済みマスは **`nil`** を返します。`if mget(x, y) == spr_id(:wall)` のように判定可能です。 |
| **`mset`** | `(cel_x = 0, cel_y = 0, val = nil)` | `nil` | タイルマップ上のセル `(cel_x, cel_y)` のタイル番号を設定します。`val` には整数IDのほか、スプライト名（`Symbol`、例: `:wall`）や1文字エイリアス（例: `"#"`）も指定可能です。`val` に `nil` を渡す（または第3引数を省略する）と該当セルを消去（空マス化）します。 |
| **`mdel`** / **`mclear`** | `(cel_x = 0, cel_y = 0)` | `nil` | タイルマップ上のセル `(cel_x, cel_y)` に配置されているタイルを消去します（`mset(cel_x, cel_y, nil)` と同等）。 |
| **`print_text`** | `(text = "", x = 0, y = 0, col = 7)` | `nil` | 文字列 `text` を左上座標 `(x, y)` 基準、色 `col` の 1-bit ドット絵フォント（ASCII: `6×8`px、日本語全角・漢字: 美咲フォント `8×8`px、半角カナ: `4×8`px）でくっきり描画します。 |

### 2.5 ホットリロードとリスタート

* `uk run` または `uk browser` 実行中にスクリプトファイルを保存すると、自動的にホットリロードが行われます。
* **オブジェクト指向シーン（`run Scene.new`）のホットリロード**:
  * スクリプト保存時、現在動作しているシーンのインスタンスおよびそのインスタンス変数（`@x`, `@y` 等）は破棄されずそのまま維持されます。
  * スクリプト全体の再評価中に実行されるトップレベルの `run(Scene.new)`（初期化）呼び出しは自動的に無視され、更新された新しいクラス定義（`update`, `draw` などのメソッド定義）のみが実行中のインスタンスへシームレスに再バインドされます。
  * 通常フレームの `update` 処理内で `run(NextScene.new)` が呼ばれた場合は、通常通り新しいシーンへ遷移します。
* **グローバル変数とタイルマップ**:
  * `$x`, `$y`, `$score` などの**グローバル変数**および `mset` による実行時のタイルマップ変更も、ホットリロード後に状態が維持されます。
  * ただし、スクリプト先頭でのグローバル変数の初期値代入コードや `__END__` 内の `@MAP` 定義そのものを書き換えた場合は、ホットリロード時も新しい初期値で上書きされます。
* **先頭からやり直す（リスタート）**:
  * ショートカットキー **`F5`** または **`Ctrl+R`**（macOS: **`Cmd+R`**）を押すと、現在のシーンやグローバル変数、タイルマップ、再生音を完全に破棄・初期化し、スクリプトを先頭からやり直すことができます。
  * スクリプト内から **`restart`**（または **`reset`**）API を呼び出してゲームを先頭からリスタートすることも可能です。

### 2.6 デバッグ機能とショートカット

* **`F3` キー**: 画面右下に現在の **FPS 値（フレームレート）** を表示・非表示切り替え。
* **`F5` / `Ctrl+R`（macOS: `Cmd+R`）**: ゲームを**先頭からリスタート**（初期化）。
* **`F8` キー**: **GIF録画の開始地点をリセット**。リングバッファをクリアし、この瞬間から最大10秒間の録画を開始します。
* **`F9` キー（または `Shift+F12`）**: **アニメーションGIFを保存**。直近最大10秒間（または直前に `F8` を押した時点から現在まで）の画面を 30FPS アニメーションGIFとして `screenshots/screenshot_XXX.gif` に連番保存します。
* **`F12` キー**: 現在の画面を**スクリーンショット撮影**。`screenshots/screenshot_XXX.png` にピクセルパーフェクトな PNG 形式（ウィンドウ倍率に応じたスケール）で連番保存されます。
* **CLIからの自動撮影**:
  * `uk run game.rb -s out.png -f 60` で指定フレーム経過後にPNGスクリーンショットを自動保存して終了します。
  * `uk run game.rb --gif out.gif -f 180 --start-frame 30 -g` で指定フレーム区間（30FPS換算）のアニメーションGIFを自動録画して終了します（`-g` でガチャキー自動連打も併用可能）。

## 3. グラフィックス仕様

### 3.1 仮想スクリーンとレンダリングパイプライン

1. **オフスクリーン描画**:
   * `draw` 内の描画命令は、すべて `256 × 256` のオフスクリーンレンダーターゲット（`FilterMode::Nearest`）に対して行われます。
2. **ピクセルパーフェクト・スケーリング**:
   * フレーム終端で実ウィンドウ（標準 `512 × 512`）のサイズを取得し、`scale = min(window_width / 256.0, window_height / 256.0)` でアスペクト比を維持したまま中央に配置（黒帯のレターボックス／ピラーボックス付き）して拡大描画します。

### 3.2 標準16色カラーパレット

色番号 `col` に範囲外の整数（負の数や `16` 以上）を指定した場合、`col % 16`（ユークリッド剰余）によって自動的に `0`〜`15` に丸められます。

| :---: | :---: | :--- | :---: | :--- |
| **0** | `0` | Black | `#000000` | `(0, 0, 0)` |
| **1** | `1` | Dark Blue | `#1D2B53` | `(29, 43, 83)` |
| **2** | `2` | Dark Purple | `#7E2553` | `(126, 37, 83)` |
| **3** | `3` | Dark Green | `#008751` | `(0, 135, 81)` |
| **4** | `4` | Brown | `#AB5236` | `(171, 82, 54)` |
| **5** | `5` | Dark Grey | `#5F574F` | `(95, 87, 79)` |

### 3.2.1 カスタムパレット定義（`@PALETTE <id>`）

`__END__` または `.spr` 内に `@PALETTE <id>`（`id` は 1 以上の整数）ブロックを記述することで、独自の16色カラーパレットを定義できます。未指定の色番号は標準PICO-8パレット（`PALETTE_RGBA`）の色が引き継がれます。
※ **パレット0番はシステムパレット（不変のPICO-8標準16色）として予約**されており、ユーザー定義で上書きすることはできません。

```ruby
__END__
# ① グリーン系パレット（パレット1番）
# ピンポイント上書き記法（インデックスは 0..15 または 0..F、コロンまたはスペース区切り）
@PALETTE 1
0: #000000  # 黒フチ
1: #006838  # 深い影の緑
3: #00B858  # 中間の緑
B: #78F878  # ハイライト黄緑
8: #F83800  # 鞍の赤
2: #A81000  # 鞍の影
7: #F8F8F8  # 白

# ② 16色一括指定記法（0番から順に割り当て）
@PALETTE 2
#000000 #1D2B53 #7E2553 #008751 #AB5236 #5F574F #C2C3C7 #FFF1E8
#FF004D #FFA300 #FFEC27 #00E436 #29ADFF #83769C #FF77A8 #FFCCAA
```

* カラーコードは `#RRGGBB`、`#RGB`、`0xRRGGBB` に対応しています。
* ゲーム起動時の標準パレットをカスタムパレットにしたい場合は、`config(palette: 1)` を指定するか、初期化時に `pal_bank(1)` を呼び出します。
* 各スプライト定義時に `@SPRITE <id> pal:<pal_id>` と指定することで、スプライトごとに適用するパレットを自由に紐付けることができます。
* `pal_bank(0)` または `pal_bank()` を呼び出すことで、いつでも確実に元の標準PICO-8パレットに戻すことができます。

### 3.3 スプライト定義フォーマット（絵文字・テキスト・Base64 PNG）

Usakame は用途に応じて以下の4通りのスプライト指定・定義方法を標準サポートしています。

#### 方法1: 標準内蔵の `16 × 16` 絵文字スプライト（定義不要）

エンジン内部に 1,400 種類の `16 × 16` ドット絵風絵文字アトラス（SFC RGB555 減色・1bit透過済み）が内蔵されており、`__END__` 定義なしで直接 `spr` に絵文字を渡して描画できます。また `@SPRITE <id> <emoji>` でスプライト番号に割り当てることも可能です。

```ruby
# 直接描画
spr("🐰", $x, $y, $flip_x, false)
spr("🐢", 100, 208)
spr("⚔️", 120, 208, false, false, 45, 1.5) # 45度回転・1.5倍スケール

__END__
# スプライト番号に絵文字を割り当てる場合
@SPRITE 10 🍎
```

#### 方法2: PNG画像 / スプライトシートからの Base64 圧縮記法（`@SHEET` / `@PNG` / `@B64`）

外部ペイントツールで作成した PNG 画像（単体スプライトやスプライトシート）を、`uk encode` コマンドで Base64 ブロックに変換してスクリプト末尾に埋め込めます。PNG バイナリの可逆圧縮がそのまま活きるため、数十個のスプライトでも数十行に収まります。

```bash
# 16x16 タイル分割の @SHEET (または 16x16 単体なら @PNG) ブロックを出力
uk encode assets/sheet.png --id 0 --tile 16x16 >> game.rb
```

```ruby
__END__
# スプライトシートを 16x16 タイル単位で分割し、ID 0, 1, 2... に連番登録
@SHEET 0 16x16
iVBORw0KGgoAAAANSUhEUgAAAIAAAACACAYAAADDPmHL...

# 単体 PNG または 16x16 圧縮パレットデータの登録
@PNG 100
iVBORw0KGgoAAAANSUhEUgAAABAAAAAQ...
```

#### 方法3: `__END__` セクションでの名前指定・2次元オートパッキング・アニメーション定義（`@SPRITE`）

スプライトヘッダーでは、明示的な整数ID指定だけでなく、**`:名前`（ラベル）による宣言的定義、複数フレームのアニメーション定義、および2次元オートパッキング**に対応しています。

* **構文フォーマット**:
  ```ruby
  # 1. 従来の明示ID指定（後方互換）
  @SPRITE 4 32x32 pal:1

  # 2. 名前（シンボル）指定 + 絵文字
  @SPRITE :wall 🧱
  @SPRITE :apple 🍎

  # 3. アニメーション（複数絵文字スペース区切り）
  @SPRITE :enemy 👾 💣

  # 4. 可変サイズ・名前指定・カスタムパレット（スロット自動配置）
  @SPRITE :boss 32x32 pal:1

  # 5. アニメーション（テキストパターンの '---' 区切り）
  @SPRITE :hero pal:1
  ...(1フレーム目のテキストパターン)...
  ---
  ...(2フレーム目のテキストパターン)...
  ```
* **サイズと2次元オートパッキング（ハイブリッド方式）**:
  * Bank 0 のグリッドは `16 × 16` スロット（各スロット `16 × 16`px）で管理されます。
  * `8x8` など 16x16 未満の小型スプライトや可変サイズ（`16x32`, `32x32`等）を定義した場合、スロットとしては必要なセル分（`ceil(w/16.0) × ceil(h/16.0)`）を占有しつつ、実サイズ `(w, h)` が保持され、描画時や中心ピボット計算に反映されます。
  * 明示ID（整数）が指定されたスプライトがまず配置され、名前指定（`:hero` 等）やID省略のスプライトは空いているスロット矩形へ自動パッキング（スロットID `1` から探索）されます。
* **アニメーションフレームの自動パディング正規化**:
  * `---` 区切りで各フレームのテキストパターンの行数や文字数が異なる場合でも、最大幅 `max_w` × 最大高さ `max_h`（または指定サイズ）に合わせて、右側および下側に透明ピクセル（`.`）が自動でパディングされ、同一サイズ・ピボットに統一されます。

#### 方法4: グローバル変数 `$SPRITES` で定義

Rubyコード内で `$SPRITES` に文字列配列の配列（テキストパターン）、または絵文字／Base64文字列を代入することでも定義できます。

```ruby
$SPRITES = [
  "🐰",
  "🐢"
]
```

### 3.4 タイルマップ定義フォーマット（`@MAP` / `$MAP`）

`__END__` セクション内に `@MAP [offset_x] [offset_y]` ブロックを記述することで、マップデータを定義できます。

* **1文字エイリアス（凡例）宣言**:
  * `@MAP` セクション冒頭に `<1文字> = <スプライト名または整数ID>`（例: `W = :wall`、`$ = :coin`、`C = :chest`）の形式で凡例を宣言できます（`W=:wall` や `W: :wall` も可、1行に複数宣言も対応）。
  * ※ エイリアス文字に `#` を使うとエディタ（VSCode等）でRubyコメントとしてシンタックスハイライトされてしまうため、壁チップ等には `W` や `X`、`+` などの英数字・記号を使用することを推奨します。
  * **引き継ぎと部分上書き**: エイリアス宣言は同一ファイル内で上から下へ引き継がれるため、最初の `@MAP` で共通の宣言を行えば、後続の `@MAP` でもそのまま同じ文字を利用できます。また、特定のマップで `W = :ice_wall` のように再宣言すると、他のエイリアスを維持したまま特定文字だけを差分上書きできます。
  * **外部ファイル**: `.map` ファイルへ分割した場合は、その `.map` ファイルの先頭でエイリアスを宣言することで、ファイル単体で自己完結して可読性を保てます。
* **1文字1タイル記法（空白・カンマなし）**:
  * `1`〜`F` がスプライト番号 `1`〜`15`、`.` または `0` が空タイルに対応します。さらに、上記で宣言された1文字エイリアス（`W` や `@` 等）もそのまま記述できます。
* **スペース／カンマ区切り記法**:
  * `1 2 10 100 .` のような数値だけでなく、`wall . apple` のようにスプライト名（`:` あり/なし両方）を直接記述できます。
* Rubyコード内でグローバル変数 `$MAP`（文字列配列または2次元整数配列）に代入することでも定義可能です。

```ruby
__END__
@SPRITE :wall 🧱
@SPRITE :apple 🍎
@SPRITE :player 🏃

@MAP 0 0
# 1文字エイリアス宣言（イコールまたはコロン区切り）
W = :wall
@ = :apple
P = :player

# 1文字エイリアスによる配置
WWWWWW
W....W
W.P@.W
WWWWWW

# またはスペース/カンマ区切り記法（シンボル名直接指定）
# wall wall   wall wall
# wall player .    wall
# wall .      apple wall
# wall wall   wall wall
```

## 4. サウンド仕様（現状と今後の実装計画）

### 4.1 現在の実装状況
* **ステータス**: **未実装**
* 現在、Rust本体（`Cargo.toml` / `src/main.rs`）にはサウンド再生用のAPIおよび音声合成処理はまだ含まれていません。
* ただし、Web（WASM）ターゲット用のJSバンドル（`web/mq_js_bundle.js`）には、`macroquad_audio` プラグイン（Web Audio APIバインディング）がすでに組み込まれています。

### 4.2 サウンド実装の設計方針案

レトロゲームエンジンとして、外部アセットファイル無しで `.rb` 1ファイル（および `uk build` の単一バイナリ）に完結できるよう、以下のような設計が適しています。

1. **波形合成（チップチューン・シンセサイザー）**
   * 矩形波（Square）、三角波（Triangle）、ノコギリ波（Sawtooth）、ノイズ（Noise）などの基本波形をRust側でPCM（WAVデータ）として動的生成し、`macroquad::audio` で再生する。
2. **API案**
   * `sfx(id, channel = -1)`: 定義済みの効果音 `id` を再生する。
   * `music(id, loop = true)`: 定義済みのBGMパターンを再生する（`-1` で停止）。
   * `tone(freq, duration, wave = 0, vol = 7)`: 周波数や長さを直接指定して単音を鳴らす。
3. **データ定義案（`__END__` セクション拡張）**
   * `@SPRITE <id>` と同様に、`@SFX <id>` や `@MUSIC <id>` セクションを `__END__` 内に記述できるようにし、MML風表記またはトラッカー風ノート表記で効果音・BGMを定義する。

## 5. リソース永続化・エディタ支援 API

Usakame では、`game.rb` 等の単一スクリプト内に Ruby コード、スプライト（`@SPRITE`）、タイルマップ（`@MAP` / `@OBJECTS`）を安全に共存・同時編集できるよう、非破壊的なセクション置換 API を提供しています。

### 5.1 スプライト／バンク保存
* **`save_resource_bank(path, bank_id = 0, format = nil)`**:
  * 指定ファイル（`game.rb` または `.spr`）へ、指定バンクのデータを非破壊パッチ保存します。
  * `Ruby` コードやセクション外のコメント、他のディレクティブは完全に保持されます。
  * `format`:
    * `"text"` / `:text`: `@SPRITE` 形式のテキストブロック（16進数行）で保存します。
    * `"b64"` / `:b64` / `true`: `@BANK <id>` (Base64 PNG) 形式で保存します。
    * `nil` / `false`（デフォルト）:
      * `bank_id == 0`: 既存ファイルに `@BANK 0` がありかつ `@SPRITE` が無い場合は Base64 を維持し、それ以外（未pack状態や新規）は AIフレンドリーな `@SPRITE` テキスト形式を維持します。
      * `bank_id > 0`: `@BANK <id>` Base64 形式で保存します。
* **`export_bank_sprites_text(path_or_bank_id = 0, bank_id = 0)`**:
  * バンク内の非空スプライトを `@SPRITE` テキスト形式（16進数ブロック）でフォーマットした文字列を返します。
  * ファイルパスを指定した場合は、既存のインラインコメントや絵文字ラベルを可能な限り引き継ぎます。

### 5.2 タイルマップ／オブジェクト保存・読み込み
* **`save_resource_map(path, map_text)`**:
  * 指定ファイル（`game.rb` または `.map`）の `@MAP` および `@OBJECTS` セクションのみを安全に差し替えて保存します。
  * `Ruby` コードや `@SPRITE` 定義、コメントは一切破壊されません。
* **`load_resource_map(path, width = nil, height = nil)`**:
  * 指定スクリプトまたは外部マップファイルからタイルIDの配列（1次元、要素数 `width * height`）を返します。未設定セルは `nil` になります。
  * `width` および `height` を省略した場合は、`@MAP` に記述されている実サイズ（幅と高さ）を自動検出します。
* **`load_resource_map_dimensions(path)`**:
  * 指定ファイルの `@MAP` セクションから実際の幅と高さを `[width, height]` 配列で返します（`@MAP` が無い場合は `nil`）。
* **`load_resource_objects(path, filter_type = nil)`**:
  * 指定ファイルの `@OBJECTS` セクションからオブジェクトの配列（各オブジェクトは Hash）を返します。

### 5.3 ファイル監視
* **`file_mtime(path)`**:
  * 指定ファイルの最終更新時刻（UNIXミリ秒、整数）を取得します（存在しない場合は `0`）。
  * 外部（VSCode 等）でのスクリプト編集やスプライト更新を検知してホットリロードする際に利用します。

## 6. 今後追加が検討される主なAPI候補

一般的なレトロゲームエンジンの仕様に基づき、今後以下のAPI群の実装が候補となります。

* **入力拡張**:
  * マウス・タッチ座標取得（`mouse_x`, `mouse_y`, `mouse_btn`）
* **図形・スプライト描画拡張**:
  * `pget(x, y)`: 指定座標のパレット色取得
  * `spr` の複数タイル連結対応（`w`, `h` 引数追加）または `sspr`（テクスチャ領域指定描画）
* **サウンド**:
  * `sfx`, `music`, `tone`
