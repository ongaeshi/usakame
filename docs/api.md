# Usakame Engine API & グラフィックス・サウンド仕様書

このドキュメントでは、レトロゲームエンジン **Usakame** の現在のAPI一覧、グラフィックス描画仕様、およびサウンド機能の現状と設計方針をまとめています。

---

### 1. エンジン基本仕様

| 項目 | 仕様 |
| :--- | :--- |
| **仮想画面解像度** | `256 × 256` ピクセル固定 |
| **初期ウィンドウサイズ** | `512 × 512` ピクセル（2倍スケール、リサイズ可能・アスペクト比維持） |
| **カラーパレット** | 標準16色パレット（テキストスプライト・図形描画用）＋ フルカラーRGBA / 15-bit RGB555（PNG・絵文字スプライト用） |
| **スプライト基本サイズ** | `16 × 16` ピクセル（標準内蔵絵文字 1,400種・テキスト・Base64 PNG対応） |
| **フレームレート** | 約 60 FPS |
| **スクリプト言語** | Ruby（mrubyedge / mruby-compiler2 によるバイトコード実行） |

---

## 2. 現在のAPIリスト

すべてのエンジンAPIはRubyのトップレベル（`Object`クラスのメソッド）として定義されており、どこからでも直接呼び出すことができます。

### 2.1 ライフサイクルコールバック

ユーザースクリプト側で以下のメソッドを定義すると、エンジンのメインループから毎フレーム自動的に呼び出されます。

* **`update`**
  * 毎フレーム1回、描画前に呼び出されます。
  * キー入力の取得やゲーム状態の更新処理を記述します。
* **`draw`**
  * 毎フレーム1回、`update` の直後に呼び出されます。
  * `256 × 256` のオフスクリーン仮想画面に対する描画処理を記述します。

```ruby
def update
  # 毎フレームのロジック更新
end

def draw
  # 毎フレームの描画処理
end
```

### 2.2 描画API

| **`camera`** | `(x = 0, y = 0)` | `nil` | カメラオフセットを `(x, y)` に設定し、以降のすべての描画座標から `(x, y)` を減算します。引数なしで `camera()` と呼ぶと `(0, 0)` にリセットします。 |

| **`pal`** | `(c0 = nil, c1 = nil)` | `nil` | パレット色 `c0` を `c1` に置き換えて以降の図形・テキスト・スプライトを描画します。16要素の配列 `pal([c0, c1, ...])` で一括設定も可能。`pal(c0, "#RRGGBB")` や `pal(c0, r, g, b)` で指定色番号のRGB値を動的に変更することもできます。引数なしで `pal()` と呼ぶとパレット置換、`palt`、および動的RGB変更をリセットします。 |

| **`pset`** | `(x = 0, y = 0, col = 7)` | `nil` | 座標 `(x, y)` に色 `col` で `1 × 1` ピクセルの点を描画します。 |
| **`line`** | `(x0 = 0, y0 = 0, x1 = 0, y1 = 0, col = 7)` | `nil` | 始点 `(x0, y0)` から終点 `(x1, y1)` まで、ブレゼンハムアルゴリズムで太さ `1px` の直線を色 `col` で描画します。 |
| **`rect`** | `(x = 0, y = 0, w = 16, h = 16, col = 7)` | `nil` | 左上座標 `(x, y)` から幅 `w`、高さ `h` の枠線のみの矩形（太さ `1px`）を色 `col` で描画します。 |
| **`rectfill`** | `(x = 0, y = 0, w = 16, h = 16, col = 7)` | `nil` | 左上座標 `(x, y)` から幅 `w`、高さ `h` の塗りつぶし矩形を色 `col` で描画します。 |
| **`circ`** / **`circle`** | `(x = 0, y = 0, r = 4, col = 7)` | `nil` | 中心 `(x, y)`、半径 `r` の枠線のみの円（太さ `1px`、ドット対称）を色 `col` で描画します。 |
| **`circfill`** / **`circlefill`** | `(x = 0, y = 0, r = 4, col = 7)` | `nil` | 中心 `(x, y)`、半径 `r` の塗りつぶし円を色 `col` で描画します。 |
| **`oval`** / **`ellipse`** | `(x = 0, y = 0, rx = 6, ry = 4, col = 7)` | `nil` | 中心 `(x, y)`、水平半径 `rx`、垂直半径 `ry` の枠線のみの楕円（太さ `1px`、ドット対称）を色 `col` で描画します。 |
| **`ovalfill`** / **`ellipsefill`** | `(x = 0, y = 0, rx = 6, ry = 4, col = 7)` | `nil` | 中心 `(x, y)`、水平半径 `rx`、垂直半径 `ry` の塗りつぶし楕円を色 `col` で描画します。 |
| **`tri`** | `(x0 = 0, y0 = 0, x1 = 8, y1 = 0, x2 = 4, y2 = 8, col = 7)` | `nil` | 3頂点 `(x0, y0)`, `(x1, y1)`, `(x2, y2)` を結ぶ枠線のみの三角形を色 `col` で描画します。 |
| **`trifill`** | `(x0 = 0, y0 = 0, x1 = 8, y1 = 0, x2 = 4, y2 = 8, col = 7)` | `nil` | 3頂点 `(x0, y0)`, `(x1, y1)`, `(x2, y2)` で囲まれた塗りつぶし三角形を色 `col` で描画します。 |
| **`spr`** | `(id_or_emoji = 0, x = 0, y = 0, flip_x = false, flip_y = false, rotate = 0, scale = 1.0)` または `(id, x, y, w, h, flip_x, ...)` | `nil` | スプライト番号 `id`（整数）または絵文字文字列（例: `"🐰"`, `"🐢"`, `"⚔️"`）を座標 `(x, y)` に描画します。`w, h` を省略した場合は、そのスプライトの定義サイズ（`@SPRITE` で指定した 32x32 や 16x32 等、デフォルトは 16x16）で自動描画されます。第4・第5引数にタイル数 `w, h`（16px単位、例: `2, 2` で 32x32）を明示指定して描画サイズを上書きすることも可能です。`flip_x` で左右反転、`flip_y` で上下反転、`rotate` で回転角（度数法 `0`〜`360`、時計回り）、`scale` で拡大縮小率を指定でき、元のスプライト矩形の中心を基準（ピボット）として回転・スケーリングされます。 |
| **`blt`** | `(x = 0, y = 0, bank = 0, u = 0, v = 0, w = 16, h = 16, rotate = 0, scale = 1.0, pal = nil)` | `nil` | バンク `bank` の矩形領域 `(u, v, w, h)` を画面座標 `(x, y)` にピクセル転送描画します。`w` や `h` に負の値を指定すると左右・上下反転します。第10引数 `pal` にパレット番号（`0, 1, 2...`）を指定することで、特定パレットで上書き描画（色違い・パレットスワップ）が可能です。 |
| **`map`** | `(cel_x = 0, cel_y = 0, sx = 0, sy = 0, cel_w = map.width, cel_h = map.height)` | `nil` | タイルマップのセル `(cel_x, cel_y)` から幅 `cel_w` × 高さ `cel_h` セル分の領域を、画面（ワールド）座標 `(sx, sy)` を左上基準として一括描画します（`1セル = 16 × 16`px、空マスはスキップ、タイル番号 `0` も有効なタイルとして描画されます）。 |
| **`mget`** | `(cel_x = 0, cel_y = 0)` | `Integer` / `nil` | タイルマップ上のセル `(cel_x, cel_y)` に配置されているタイル番号（スプライトID）を返します。未設定セルまたは消去済みマスは **`nil`** を返します。`if mget(x, y)` でタイルの有無を判定できます。 |
| **`mset`** | `(cel_x = 0, cel_y = 0, val = nil)` | `nil` | タイルマップ上のセル `(cel_x, cel_y)` のタイル番号を `val`（0以上の整数）に設定します。`val` に `nil` を渡す（または第3引数を省略する）と該当セルを消去（空マス化）します。なお、負数（`-1` 等）を指定すると `ArgumentError` 例外が発生します（消去には `nil` または `mdel` を使用してください）。 |
| **`mdel`** / **`mclear`** | `(cel_x = 0, cel_y = 0)` | `nil` | タイルマップ上のセル `(cel_x, cel_y)` に配置されているタイルを消去します（`mset(cel_x, cel_y, nil)` と同等）。 |
| **`print_text`** | `(text = "", x = 0, y = 0, col = 7)` | `nil` | 文字列 `text` を左上座標 `(x, y)` 基準、色 `col` の 1-bit ドット絵フォント（ASCII: `6×8`px、日本語全角・漢字: 美咲フォント `8×8`px、半角カナ: `4×8`px）でくっきり描画します。 |

### 2.4 ホットリロードとリスタート

* `uk run` または `uk browser` 実行中にスクリプトファイルを保存すると、自動的にホットリロードが行われます。
* `$x`, `$y`, `$score` などの**グローバル変数**および `mset` による実行時のタイルマップ変更は、ホットリロード後も状態が維持されます。
* **先頭からやり直す（リスタート）**:
  * ショートカットキー **`F5`** または **`Ctrl+R`**（macOS: **`Cmd+R`**）を押すと、スクリプトを先頭からリスタートし、グローバル変数やタイルマップ、再生音を完全に初期状態に戻してやり直すことができます。
  * Ruby スクリプト内から **`restart`**（または **`reset`**）API を呼び出してゲームを先頭からリスタートすることも可能です。
* ただし、スクリプト先頭でのグローバル変数の**初期値定義**や `__END__` 内の `@MAP` 定義そのものを書き換えた場合は、ホットリロード時も新しい初期値で上書きされます。

### 2.5 デバッグ機能とショートカット

* **`F3` キー**: 画面右下に現在の **FPS 値（フレームレート）** を表示・非表示切り替え。
* **`F5` / `Ctrl+R`（macOS: `Cmd+R`）**: ゲームを**先頭からリスタート**（初期化）。
* **`F12` キー**: 現在の画面を**スクリーンショット撮影**。`screenshots/screenshot_XXX.png` にピクセルパーフェクトな PNG 形式（ウィンドウ倍率に応じたスケール）で連番保存されます。

## 3. グラフィックス仕様

### 3.1 仮想スクリーンとレンダリングパイプライン

1. **オフスクリーン描画**:
   * `draw` 内の描画命令は、すべて `256 × 256` のオフスクリーンレンダーターゲット（`FilterMode::Nearest`）に対して行われます。
2. **ピクセルパーフェクト・スケーリング**:
   * フレーム終端で実ウィンドウ（標準 `512 × 512`）のサイズを取得し、`scale = min(window_width / 256.0, window_height / 256.0)` でアスペクト比を維持したまま中央に配置（黒帯のレターボックス／ピラーボックス付き）して拡大描画します。

### 3.2 標準16色カラーパレット

色番号 `col` に範囲外の整数（負の数や `16` 以上）を指定した場合、`col % 16`（ユークリッド剰余）によって自動的に `0`〜`15` に丸められます。

### 3.2.1 カスタムパレット定義（`@PALETTE <id>`）

`__END__` または `.spr` 内に `@PALETTE <id>`（`id` は 1 以上の整数）ブロックを記述することで、独自の16色カラーパレットを定義できます。未指定の色番号は標準PICO-8パレット（`PALETTE_RGBA`）の色が引き継がれます。
※ **パレット0番はシステムパレット（不変のPICO-8標準16色）として予約**されており、ユーザー定義で上書きすることはできません。

```ruby
__END__
# ① グリーン系パレット（パレット1番）
# ピンポイント上書き記法（インデックスは 0..15 または 0..F、コロンまたはスペース区切り）
@PALETTE 1
0: #000000  # 黒フチ
1: #006838  # 深い影の緑
3: #00B858  # 中間の緑
B: #78F878  # ハイライト黄緑
8: #F83800  # 鞍の赤
2: #A81000  # 鞍の影
7: #F8F8F8  # 白

# ② 16色一括指定記法（0番から順に割り当て）
@PALETTE 2
#000000 #1D2B53 #7E2553 #008751 #AB5236 #5F574F #C2C3C7 #FFF1E8
#FF004D #FFA300 #FFEC27 #00E436 #29ADFF #83769C #FF77A8 #FFCCAA
```

* カラーコードは `#RRGGBB`、`#RGB`、`0xRRGGBB` に対応しています。
* ゲーム起動時の標準パレットをカスタムパレットにしたい場合は、`config(palette: 1)` を指定するか、初期化時に `pal_bank(1)` を呼び出します。
* 各スプライト定義時に `@SPRITE <id> pal:<pal_id>` と指定することで、スプライトごとに適用するパレットを自由に紐付けることができます。
* `pal_bank(0)` または `pal_bank()` を呼び出すことで、いつでも確実に元の標準PICO-8パレットに戻すことができます。

### 3.3 スプライト定義フォーマット（絵文字・テキスト・Base64 PNG）

Usakame は用途に応じて以下の4通りのスプライト指定・定義方法を標準サポートしています。

#### 方法1: 標準内蔵の `16 × 16` 絵文字スプライト（定義不要）

エンジン内部に 1,400 種類の `16 × 16` ドット絵風絵文字アトラス（SFC RGB555 減色・1bit透過済み）が内蔵されており、`__END__` 定義なしで直接 `spr` に絵文字を渡して描画できます。また `@SPRITE <id> <emoji>` でスプライト番号に割り当てることも可能です。

```ruby
# 直接描画
spr("🐰", $x, $y, $flip_x, false)
spr("🐢", 100, 208)
spr("⚔️", 120, 208, false, false, 45, 1.5) # 45度回転・1.5倍スケール

__END__
# スプライト番号に絵文字を割り当てる場合
@SPRITE 10 🍎
```

#### 方法2: PNG画像 / スプライトシートからの Base64 圧縮記法（`@SHEET` / `@PNG` / `@B64`）

外部ペイントツールで作成した PNG 画像（単体スプライトやスプライトシート）を、`uk encode` コマンドで Base64 ブロックに変換してスクリプト末尾に埋め込めます。PNG バイナリの可逆圧縮がそのまま活きるため、数十個のスプライトでも数十行に収まります。

```bash
# 16x16 タイル分割の @SHEET (または 16x16 単体なら @PNG) ブロックを出力
uk encode assets/sheet.png --id 0 --tile 16x16 >> game.rb
```

```ruby
__END__
# スプライトシートを 16x16 タイル単位で分割し、ID 0, 1, 2... に連番登録
@SHEET 0 16x16
iVBORw0KGgoAAAANSUhEUgAAAIAAAACACAYAAADDPmHL...

# 単体 PNG または 16x16 圧縮パレットデータの登録
@PNG 100
iVBORw0KGgoAAAANSUhEUgAAABAAAAAQ...
```

#### 方法3: `__END__` セクションでの可変サイズテキストパターン定義（`@SPRITE <id> [WIDTHxHEIGHT] [pal:<id>]`）

`0`〜`9`, `A`〜`F`（パレット色 `0`〜`15`）および `.` またはスペース（透明ピクセル）を用いて、テキスト行で直接ドット絵を記述できます。
基本の `16 × 16` はもちろん、**`32 × 32`（大型キャラ・ボス）、`16 × 32`（背の高いキャラクター）、`24 × 24`** などの可変サイズに対応しています。

* **サイズ指定**:
  * `@SPRITE 0 32x32` や `@SPRITE 4 16x32` のように明示的に指定可能。
  * サイズ指定を省略した場合は、**記述された行の最大文字数と行数から自動検出**されます（16x16 の記述は一切変更不要）。
* **パレット指定**:
  * スプライトヘッダーに `pal:<id>`（例: `@SPRITE 0 32x32 pal:1`）を付与することで、そのスプライトに適用するパレットバンク番号を指定できます（省略時はデフォルトパレット0番）。
* **バンク（Bank 0）への配置とスロット管理**:
  * スプライト ID `id`（0..255）の原点は、Bank 0 上の `slot_x = (id % 16) * 16`、`slot_y = (id / 16) * 16` と 1:1 で一致して矩形展開されます。
  * 例えば ID 0 に 32x32 を配置した場合、スロット 0, 1, 16, 17（32x32 px）を占有します。次のスプライトは空いているスロット（例: スロット 2 や 4）を指定してください。万が一スロットが重複した場合はコンソールに警告（Warning）が出力されます。

```ruby
__END__
# 16x32 の背の高いキャラ（サイズ省略でも行数から自動判定）
@SPRITE 0 16x32
................
...000000000....
...(16文字 x 32行)...
................

# 32x32 の大型キャラ（カスタムパレット1番を指定）
# スロット 0 が (0..31, 0..31) を占有するため、次はスロット 2 または 4 以降に配置
@SPRITE 4 32x32 pal:1
................................
...0000000000000000000000000....
...(32文字 x 32行)...
................................
```

#### 方法4: グローバル変数 `$SPRITES` で定義

Rubyコード内で `$SPRITES` に文字列配列の配列（テキストパターン）、または絵文字／Base64文字列を代入することでも定義できます。

```ruby
$SPRITES = [
  "🐰",
  "🐢"
]
```

### 3.4 タイルマップ定義フォーマット（`@MAP` / `$MAP`）

`__END__` セクション内に `@MAP [offset_x] [offset_y]` ブロックを記述することで、マップデータを定義できます。
* **1文字1タイル記法（空白・カンマなし）**: `1`〜`F` がスプライト番号 `1`〜`15`、`.` または `0` が空タイルに対応します。
* **スペース／カンマ区切り記法**: `1 2 10 100 .` のように空白またはカンマで区切ることで、`16` 以上の任意のスプライト番号も指定できます。
* Rubyコード内でグローバル変数 `$MAP`（文字列配列または2次元整数配列）に代入することでも定義可能です。

```ruby
__END__
@SPRITE 1 🌲
@SPRITE 2 🍎

@MAP 0 0
1111111111111111
1....2......2..1
1111111111111111
```

## 4. サウンド仕様（現状と今後の実装計画）

### 4.1 現在の実装状況
* **ステータス**: **未実装**
* 現在、Rust本体（`Cargo.toml` / `src/main.rs`）にはサウンド再生用のAPIおよび音声合成処理はまだ含まれていません。
* ただし、Web（WASM）ターゲット用のJSバンドル（`web/mq_js_bundle.js`）には、`macroquad_audio` プラグイン（Web Audio APIバインディング）がすでに組み込まれています。

### 4.2 サウンド実装の設計方針案

レトロゲームエンジンとして、外部アセットファイル無しで `.rb` 1ファイル（および `uk build` の単一バイナリ）に完結できるよう、以下のような設計が適しています。

1. **波形合成（チップチューン・シンセサイザー）**
   * 矩形波（Square）、三角波（Triangle）、ノコギリ波（Sawtooth）、ノイズ（Noise）などの基本波形をRust側でPCM（WAVデータ）として動的生成し、`macroquad::audio` で再生する。
2. **API案**
   * `sfx(id, channel = -1)`: 定義済みの効果音 `id` を再生する。
   * `music(id, loop = true)`: 定義済みのBGMパターンを再生する（`-1` で停止）。
   * `tone(freq, duration, wave = 0, vol = 7)`: 周波数や長さを直接指定して単音を鳴らす。
3. **データ定義案（`__END__` セクション拡張）**
   * `@SPRITE <id>` と同様に、`@SFX <id>` や `@MUSIC <id>` セクションを `__END__` 内に記述できるようにし、MML風表記またはトラッカー風ノート表記で効果音・BGMを定義する。

## 5. リソース永続化・エディタ支援 API

Usakame では、`game.rb` 等の単一スクリプト内に Ruby コード、スプライト（`@SPRITE`）、タイルマップ（`@MAP` / `@OBJECTS`）を安全に共存・同時編集できるよう、非破壊的なセクション置換 API を提供しています。

### 5.1 スプライト／バンク保存
* **`save_resource_bank(path, bank_id = 0, format = nil)`**:
  * 指定ファイル（`game.rb` または `.spr`）へ、指定バンクのデータを非破壊パッチ保存します。
  * `Ruby` コードやセクション外のコメント、他のディレクティブは完全に保持されます。
  * `format`:
    * `"text"` / `:text`: `@SPRITE` 形式のテキストブロック（16進数行）で保存します。
    * `"b64"` / `:b64` / `true`: `@BANK <id>` (Base64 PNG) 形式で保存します。
    * `nil` / `false`（デフォルト）:
      * `bank_id == 0`: 既存ファイルに `@BANK 0` がありかつ `@SPRITE` が無い場合は Base64 を維持し、それ以外（未pack状態や新規）は AIフレンドリーな `@SPRITE` テキスト形式を維持します。
      * `bank_id > 0`: `@BANK <id>` Base64 形式で保存します。
* **`export_bank_sprites_text(path_or_bank_id = 0, bank_id = 0)`**:
  * バンク内の非空スプライトを `@SPRITE` テキスト形式（16進数ブロック）でフォーマットした文字列を返します。
  * ファイルパスを指定した場合は、既存のインラインコメントや絵文字ラベルを可能な限り引き継ぎます。

### 5.2 タイルマップ／オブジェクト保存
* **`save_resource_map(path, map_text)`**:
  * 指定ファイル（`game.rb` または `.map`）の `@MAP` および `@OBJECTS` セクションのみを安全に差し替えて保存します。
  * `Ruby` コードや `@SPRITE` 定義、コメントは一切破壊されません。

### 5.3 ファイル監視
* **`file_mtime(path)`**:
  * 指定ファイルの最終更新時刻（UNIXミリ秒、整数）を取得します（存在しない場合は `0`）。
  * 外部（VSCode 等）でのスクリプト編集やスプライト更新を検知してホットリロードする際に利用します。
