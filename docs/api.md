# Usakame Engine API & グラフィックス・サウンド仕様書

このドキュメントでは、レトロゲームエンジン **Usakame** の現在のAPI一覧、グラフィックス描画仕様、およびサウンド機能の現状と設計方針をまとめています。

---

### 1. エンジン基本仕様

| 項目 | 仕様 |
| :--- | :--- |
| **仮想画面解像度** | `256 × 256` ピクセル固定 |
| **初期ウィンドウサイズ** | `512 × 512` ピクセル（2倍スケール、リサイズ可能・アスペクト比維持） |
| **カラーパレット** | PICO-8 準拠 16色パレット（テキストスプライト・図形描画用）＋ フルカラーRGBA / 15-bit RGB555（PNG・絵文字スプライト用） |
| **スプライト基本サイズ** | `16 × 16` ピクセル（標準内蔵絵文字 1,400種・テキスト・Base64 PNG対応） |
| **フレームレート** | 約 60 FPS |
| **スクリプト言語** | Ruby（mrubyedge / mruby-compiler2 によるバイトコード実行） |

---

## 2. 現在のAPIリスト

すべてのエンジンAPIはRubyのトップレベル（`Object`クラスのメソッド）として定義されており、どこからでも直接呼び出すことができます。

### 2.1 ライフサイクルコールバック

ユーザースクリプト側で以下のメソッドを定義すると、エンジンのメインループから毎フレーム自動的に呼び出されます。

* **`update`**
  * 毎フレーム1回、描画前に呼び出されます。
  * キー入力の取得やゲーム状態の更新処理を記述します。
* **`draw`**
  * 毎フレーム1回、`update` の直後に呼び出されます。
  * `256 × 256` のオフスクリーン仮想画面に対する描画処理を記述します。

```ruby
def update
  # 毎フレームのロジック更新
end

def draw
  # 毎フレームの描画処理
end
```

### 2.2 描画API

| メソッド | 引数とデフォルト値 | 戻り値 | 説明 |
| :--- | :--- | :--- | :--- |
| **`cls`** | `(col = 0)` | `nil` | 仮想画面全体を指定したパレット色 `col` で塗りつぶしてクリアします。 |
| **`pset`** | `(x = 0, y = 0, col = 7)` | `nil` | 座標 `(x, y)` に色 `col` で `1 × 1` ピクセルの点を描画します。 |
| **`rectfill`** | `(x = 0, y = 0, w = 16, h = 16, col = 7)` | `nil` | 左上座標 `(x, y)` から幅 `w`、高さ `h` の塗りつぶし矩形を色 `col` で描画します。 |
| **`spr`** | `(id_or_emoji = 0, x = 0, y = 0, flip_x = false, flip_y = false, rotate = 0, scale = 1.0)` | `nil` | スプライト番号 `id`（整数）または絵文字文字列（例: `"🐰"`, `"🐢"`, `"⚔️"`）を座標 `(x, y)` に描画します。`flip_x` で左右反転、`flip_y` で上下反転、`rotate` で回転角（度数法 `0`〜`360`、時計回り）、`scale` で拡大縮小率を指定でき、元のスプライト矩形の中心を基準（ピボット）として回転・スケーリングされます。 |
| **`print_text`** | `(text = "", x = 0, y = 0, col = 7)` | `nil` | 文字列 `text` を左上座標 `(x, y)` 基準、色 `col` の 1-bit ドット絵フォント（ASCII: `6×8`px、日本語全角・漢字: 美咲フォント `8×8`px、半角カナ: `4×8`px）でくっきり描画します。 |

### 2.3 入力API

| メソッド | 引数とデフォルト値 | 戻り値 | 説明 |
| :--- | :--- | :--- | :--- |
| **`btn`** | `(id = 0)` | `true` / `false` | 指定したボタン `id` が現在押されているかどうかを返します。 |

#### ボタンIDとキー割り当て

| ボタンID | 用途 | 対応キーボード入力 |
| :---: | :--- | :--- |
| **`0`** | 左 (Left) | `← (Left)` または `A` |
| **`1`** | 右 (Right) | `→ (Right)` または `D` |
| **`2`** | 上 (Up) | `↑ (Up)` または `W` |
| **`3`** | 下 (Down) | `↓ (Down)` または `S` |
| **`4`** | ボタン1 (Action A) | `Z` または `Space` |
| **`5`** | ボタン2 (Action B) | `X` または `Enter` |

### 2.4 ホットリロードと状態保持

* `uk run` または `uk browser` 実行中にスクリプトファイルを保存すると、自動的にホットリロードが行われます。
* `$x`, `$y`, `$score` などの**グローバル変数**は、ホットリロード後も実行中の値が維持されます。
* ただし、スクリプト先頭でのグローバル変数の**初期値定義そのものを書き換えた場合**は、新しい初期値で上書きされます。

## 3. グラフィックス仕様

### 3.1 仮想スクリーンとレンダリングパイプライン

1. **オフスクリーン描画**:
   * `draw` 内の描画命令は、すべて `256 × 256` のオフスクリーンレンダーターゲット（`FilterMode::Nearest`）に対して行われます。
2. **ピクセルパーフェクト・スケーリング**:
   * フレーム終端で実ウィンドウ（標準 `512 × 512`）のサイズを取得し、`scale = min(window_width / 256.0, window_height / 256.0)` でアスペクト比を維持したまま中央に配置（黒帯のレターボックス／ピラーボックス付き）して拡大描画します。

### 3.2 16色カラーパレット（PICO-8準拠）

色番号 `col` に範囲外の整数（負の数や `16` 以上）を指定した場合、`col % 16`（ユークリッド剰余）によって自動的に `0`〜`15` に丸められます。

### 3.3 スプライト定義フォーマット（絵文字・テキスト・Base64 PNG）

Usakame は用途に応じて以下の4通りのスプライト指定・定義方法を標準サポートしています。

#### 方法1: 標準内蔵の `16 × 16` 絵文字スプライト（定義不要）

エンジン内部に 1,400 種類の `16 × 16` ドット絵風絵文字アトラス（SFC RGB555 減色・1bit透過済み）が内蔵されており、`__END__` 定義なしで直接 `spr` に絵文字を渡して描画できます。また `@SPRITE <id> <emoji>` でスプライト番号に割り当てることも可能です。

```ruby
# 直接描画
spr("🐰", $x, $y, $flip_x, false)
spr("🐢", 100, 208)
spr("⚔️", 120, 208, false, false, 45, 1.5) # 45度回転・1.5倍スケール

__END__
# スプライト番号に絵文字を割り当てる場合
@SPRITE 10 🍎
```

#### 方法2: PNG画像 / スプライトシートからの Base64 圧縮記法（`@SHEET` / `@PNG` / `@B64`）

外部ペイントツールで作成した PNG 画像（単体スプライトやスプライトシート）を、`uk encode` コマンドで Base64 ブロックに変換してスクリプト末尾に埋め込めます。PNG バイナリの可逆圧縮がそのまま活きるため、数十個のスプライトでも数十行に収まります。

```bash
# 16x16 タイル分割の @SHEET (または 16x16 単体なら @PNG) ブロックを出力
uk encode assets/sheet.png --id 0 --tile 16x16 >> game.rb
```

```ruby
__END__
# スプライトシートを 16x16 タイル単位で分割し、ID 0, 1, 2... に連番登録
@SHEET 0 16x16
iVBORw0KGgoAAAANSUhEUgAAAIAAAACACAYAAADDPmHL...

# 単体 PNG または 16x16 圧縮パレットデータの登録
@PNG 100
iVBORw0KGgoAAAANSUhEUgAAABAAAAAQ...
```

#### 方法3: `__END__` セクションでの `16 × 16` テキストパターン定義（`@SPRITE <id>`）

`0`〜`9`, `A`〜`F`（パレット色 `0`〜`15`）および `.` またはスペース（透明ピクセル）を用いて、16文字×16行のテキストで直接ドット絵を記述できます。


#### 方法4: グローバル変数 `$SPRITES` で定義

Rubyコード内で `$SPRITES` に文字列配列の配列（テキストパターン）、または絵文字／Base64文字列を代入することでも定義できます。

```ruby
$SPRITES = [
  "🐰",
  "🐢"
]
```

## 4. サウンド仕様（現状と今後の実装計画）

### 4.1 現在の実装状況
* **ステータス**: **未実装**
* 現在、Rust本体（`Cargo.toml` / `src/main.rs`）にはサウンド再生用のAPIおよび音声合成処理はまだ含まれていません。
* ただし、Web（WASM）ターゲット用のJSバンドル（`web/mq_js_bundle.js`）には、`macroquad_audio` プラグイン（Web Audio APIバインディング）がすでに組み込まれています。

### 4.2 サウンド実装の設計方針案

レトロゲームエンジンとして、外部アセットファイル無しで `.rb` 1ファイル（および `uk build` の単一バイナリ）に完結できるよう、以下のような設計が適しています。

1. **波形合成（チップチューン・シンセサイザー）**
   * 矩形波（Square）、三角波（Triangle）、ノコギリ波（Sawtooth）、ノイズ（Noise）などの基本波形をRust側でPCM（WAVデータ）として動的生成し、`macroquad::audio` で再生する。
2. **API案**
   * `sfx(id, channel = -1)`: 定義済みの効果音 `id` を再生する。
   * `music(id, loop = true)`: 定義済みのBGMパターンを再生する（`-1` で停止）。
   * `tone(freq, duration, wave = 0, vol = 7)`: 周波数や長さを直接指定して単音を鳴らす。
3. **データ定義案（`__END__` セクション拡張）**
   * `@SPRITE <id>` と同様に、`@SFX <id>` や `@MUSIC <id>` セクションを `__END__` 内に記述できるようにし、MML風表記またはトラッカー風ノート表記で効果音・BGMを定義する。

## 5. 今後追加が検討される主なAPI候補

PICO-8 / Pyxel 等のレトロゲームエンジンを参考にした場合、今後以下のAPI群の実装が候補となります。

* **入力拡張**:
  * `btnp(id)`: ボタンが押された瞬間（エッジ判定／キーリピート付き）のみ `true` を返す
  * マウス・タッチ座標取得（`mouse_x`, `mouse_y`, `mouse_btn`）
* **図形描画拡張**:
  * `rect(x, y, w, h, col)`: 枠線のみの矩形
  * `line(x0, y0, x1, y1, col)`: 直線描画
  * `circ(x, y, r, col)` / `circfill(x, y, r, col)`: 円・塗りつぶし円
  * `pget(x, y)`: 指定座標のパレット色取得
* **スプライト・タイルマップ・パレット操作**:
  * `spr` の複数タイル連結対応（`w`, `h` 引数追加）または `sspr`（テクスチャ領域指定描画）
  * `pal(c0, c1)` / `palt(col, transparent)`: パレット色差し替え・透明色変更
  * `map` / `mget` / `mset`: タイルマップ描画・取得・変更（`@MAP` セクション）
  * `camera(x, y)` / `clip(x, y, w, h)`: カメラオフセット・描画クリッピング
* **サウンド**:
  * `sfx`, `music`, `tone`
